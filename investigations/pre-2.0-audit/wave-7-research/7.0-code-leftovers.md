  3. `handle_event(:internal, :resume, :idle, _)` (`server.ex:882-893`) → `close_resumed_batch/1` (`:1336-1348`) → `Turn.resume/1` (`turn.ex:361-363`: `:maybe_compact` and then the next model call).

## 5. Proposed approach

### 5.1 A4: render each output once in Dispatch (wire bytes unchanged)

- `lib/normandy/components/tool_result.ex`: new `@doc false` `render/1 :: {:ok, String.t()} | {:error, Exception.t()}`.
  A binary gives `{:ok, b}` (the UTF-8 check stays in Dispatch), a number `to_string/1`, anything else
  `sort_keys` + `encode!` inside `try`/`rescue`. `render_output/1` becomes `render/1` that raises.
  Text is unchanged, so memory, cap and wire stay byte-identical.
- `lib/normandy/agents/dispatch.ex`:
  - `wrap_output/2` and `wrap_error/2` call `render/1` once (in place of `JSON.encode/1`) and return the result
    plus `rendered = {output, text}`.
  - `execute/4`: drop the `ensure_encodable/1` at `:317` when the `after_tool` slot returned the same
    output (`result.output === rendered_output`: `=:=` returns at once for an identical term); otherwise
    render again.
  - `finish/3` → private `finish/4` taking the known rendering. When the output is unchanged
    (`===`), it reuses the text for the encodability and UTF-8 decision and for `cap_text/5`. Otherwise
    it renders once and uses that text for both. `finish/3` (ServerGlue, denials) renders once.
  - `ensure_encodable/1` and the second check fold into that one rendering. Item 11: `unencodable/1` describes a
    `Jason.EncodeError` by type, not by `Exception.message/1`.
- Count after: executed result **2** (Dispatch 1 + memory 1) with the cap on or off; denial 2
  (was 3 with the cap); +1 for each hook that changes the output.
- Checks: `linear_history_test.exs` `@per_result 5 → 2` and its moduledoc; a new property in
  `test/agents/dispatch_render_test.exs`: for generated terms (maps with atom, string and tuple keys,
  improper lists, pids, invalid UTF-8), `match?({:ok, _}, Normandy.JSON.encode(t)) ==
  match?({:ok, _}, ToolResult.render(t))`, so the set of outputs that fail encoding does not change. Plus
  `wire_identity_test.exs`, `tool_result_cap_test.exs`, `model_text_key_order_test.exs` unchanged and green.
  One body for all five paths: no interpreter change. No telemetry change.

### 5.2 H10: three parts, all in `Turn.Server`

No `SessionStore` callback change, no persisted-format change (`Turn.State` is untouched), no Turn
core effect (so no `Turn.Driver`/`Turn.Inline` wiring; BaseAgent `run/3`/`stream/3` have no store).

- **(a) Say it.** `{:finalize, _}`/`{:fail, _}` log `Logger.warning("normandy turn state not saved
  …: #{Describe.reason_tag(reason)}")` with `session_id`. No new telemetry event (Q #1 offers one).
- **(b) Retry while the process lives.** New `Data` field `unsaved_terminal :: Turn.State.t() | nil`,
  set when a terminal save fails. It is retried (1) at admission of the next `{:turn, …}`
  (`server.ex:832`), before `admit/2`; a failure replies `:persist_failed` `{:store_exit | reason}` like an
  in-turn save and starts nothing, and (2) at `:state_timeout :passivate` (`server.ex:991`). On
  failure the server stays alive and re-arms the idle timeout, so it stays registered: the reaper
  answers `:running` and `Session.run/2` routes to it (Q #2). A retry that succeeds clears the field.
- **(c) Resume guard.** In `handle_event(:internal, :resume, :idle, _)`, before
  `start_resumed_run_span/1`: if the state is `:steering` and the memory's last message is an
  assistant message with no tool calls (the turn's answer is already stored), the server makes no model call. It saves
  `%{state | status: :stopped}` with `inflight?: false`, logs once at `:info`, and stays `:idle`. This
  also covers the window that exists without any store fault: a crash between the answer's
  append and the terminal save.
- Not proposed: a reaper-only history check (it covers one of the three restart routes), or a
  separate index-clear callback (the store that failed the save is usually still failing, and it
  would need all 5 backends plus the contract).

Deterministic tests (new `test/agents/turn/terminal_save_test.exs`, `async: true`, a switch store
like `ErroringStore` that fails `save_turn_state/4` only for terminal statuses and records op order):
1. A tool turn whose terminal save fails replies `{:ok, _}` and logs the warning with the tag
   (`Normandy.Test.OwnLog.capture/2`); `InMemory.list_resumable/1` still lists the session.
2. Store up, next `Turn.Server.run/2`: the recorded ops show the old `:stopped` save before the new user
   `append_entry`; afterwards the session is not listed.
3. Store still down, next run: `{:error, %TurnError{type: :persist_failed}}`, and nothing was appended.
4. Resume guard: seed history `[user, assistant(tool_use), tool, assistant(text)]` plus a `:steering`
   state with `inflight: true`, and start eager with a `call_llm` handler that sends `:llm_called`. After
   `:sys.get_state(pid)` (the internal `:resume` event runs before it), the state is `:idle`,
   `refute_received :llm_called`, `load_turn_state` is `:stopped`, and `list_resumable` is `{:ok, []}`.
5. Passivation retry: `idle_timeout_ms: 20`, store down, then up; `wait_until` the session is unlisted
