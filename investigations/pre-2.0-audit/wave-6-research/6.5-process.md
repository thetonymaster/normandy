### A7 — inline `AgentProcess` runs the whole turn inside `handle_call`

### SEC-14 — `AgentProcess.run_async` unsupervised, unbounded tasks

- `:server` cast: `Task.start(fn -> ... Turn.Session.run(session, user_input) ... end)` (`agent_process.ex:635-667`).
  Catches every kind, always replies to `reply_to`. Unsupervised, unlinked, unbounded. Concurrent turns on one
  session do not run in parallel (Turn.Server postpones them), so N casts are N processes blocked in
  `Server.run/2` (`:infinity`).
- Inline cast: `Task.start(fn -> handle_async_run(state.agent, input, state.agent_id) end)` (`:669-690`,
  `handle_async_run/3` at `:785-792`). Unsupervised, unlinked, unbounded, **runs N LLM turns concurrently** from
  the same memory snapshot, discards the updated agent (memory never persists: July MEDIUM), `rescue` only, so
  an exit or throw sends nothing to `reply_to` (a bare `receive` consumer hangs). The closure captures the whole
  `state` map (`state.agent`, `state.agent_id` referenced inside the fn).
- Both kinds outlive the AgentProcess (`Task.start` is unlinked).
- `run_count`/`last_run` are bumped at cast time (`:666, 682-687`), not at completion.
- Tests: `agent_process_test.exs:122-147` (cast replies a Normandy failure / raised bug bare), `:150-177`
  (reply, no reply, stats counted — uses `wait_until`), `agent_process_server_test.exs:197-240` (server cast
  delivers result / crash error), `:426-439` (run/3 and cast/3 reply the same exception for each failure kind).

## Proposed approach

### PERF-16 (`OtelCtx`): probe once
- Add a private `loaded?(module)` that caches `Code.ensure_loaded?(module)` in `:persistent_term` under
  `{Normandy.Telemetry.OtelCtx, module}`; the `function_exported?/3` checks stay (cheap, no code server). Use it
  at all five sites. One `persistent_term.put` per module per node, the first time.
- Known limit, in the moduledoc: OTel loaded *after* the first probe is not seen until restart.
- Test (deterministic, OTel present in test env): expose `@doc false def __loaded__?(module)`; erase the key for a
  module that does not exist (`NoSuchOtelModule`), trace `:code_server` receives, call it 100 times, assert
  exactly 1 code-server message and `false`. Plus `otel_ctx_test.exs` unchanged. No telemetry events change.

### PERF-15 (`delete_turn/2`): one pass
- Replace `after_deleted?/3` with a set computed once: build `children = parent_id => [ids]` from
  `memory.entries` (O(N)), walk from every deleted id through `children` with a visited set, and take the
  descendants that are not deleted. Drop thinking for entries in that set. Cycles terminate (visited set); a
  dangling `parent_id` is just a key with no entry.
- Tests: (a) 20 000-entry chain, delete the first turn, under `Task.await(..., 5_000)` — today ≈ 12 s by
  extrapolation of the table above, after the fix tens of ms, so a 100× margin and no ratio timing; (b) survivor
  cycle not touching the deleted turn returns (under `Task.await` 2 000 as in `:326-347`); (c) dangling
  `parent_id` does not raise; existing thinking tests `:381-391` unchanged.

### A7 + PERF-13: non-blocking inline engine with a FIFO run queue
- Keep `turn_engine: :inline` as the default (Q1). Inline runs leave `handle_call`: state gains
  `running: nil | {mref, worker_pid, op}` and `queue: :queue.queue(op)` where `op` is `{:run, from, input,
  otel_ctx}`, `{:cast, reply_to, input, otel_ctx}` or `{:update, from, update_fn}`. One worker at a time, started
  from the committed `state.agent`; its `{:run_result, ...}` commits the updated agent, replies, bumps stats, and
  starts the next op.
- `update_agent/2` is queued behind in-flight runs (same ordering as today, where it waited for the run); it
  must not overwrite a run's memory. `get_agent/1`, `get_id/1`, `get_stats/1`, `approve/2` answer at once
  (`get_agent` returns the last committed agent).
- Worker: no monitor-ref handshake. `spawn_monitor` the worker; it reports `{:run_result, self(), result}` and
  the server keys `running` by pid/mref, so `agent_process.ex:702-705` goes away (also apply to `spawn_run/3`
  for `:server` mode). The worker does the same `try/rescue` as `handle_call` today, so an inline raise is still
  replied bare (`turn_error.ex:11-15` contract); a worker that dies (killed) is a `:task_down` `TurnError`, as in
  `:server` mode — document that in `turn_error.ex:11-15`. The worker monitors the AgentProcess and exits if it
  dies (the `run_while_server_alive/3` shape, `server.ex:1443-1454`), so a turn never outlives its process.
- A queued `{:run, from, ...}` whose caller is dead is dropped when dequeued (`Process.alive?(elem(from, 0))`
  check; no extra monitor needed), so killed `Reactive` waiters do not leave work behind.
- PERF-13: `run/3`'s `:timeout` default becomes `:infinity` (`agent_process.ex:182`, table `options.ex:28`), as
  `Turn.Server.run/2`. Reactive's pid branch then waits as long as Reactive's own `:timeout` allows (its task is
  killed past it).
- Tests (gate, no sleeps): a `StubClient` whose `reply` sends `{:llm_started, self()}` and blocks on
  `:release`. (1) During the gated run, `get_stats/1`, `get_id/1`, `get_agent/1` return (a blocking
  implementation would exit with `{:timeout, _}`), then release and the run's result arrives. (2) Two runs from
  two tasks: the second's `:llm_started` arrives only after the first is released; final memory holds both turns
  (4 messages). (3) `update_agent/2` issued during a gated run returns after it and the next run sees both the
  update and the first run's memory. (4) `AgentProcess.stop/1` during a gated run: the worker pid from
  `:llm_started` is dead (`assert_receive {:DOWN, ...}` on a monitor). (5) PERF-13: the run option schema's
  `:timeout` default is `:infinity` (add `__opts_schema__(:run)`). Existing `agent_process_test.exs`,
  `span_hierarchy_test.exs:693-735`, `log_policy_test.exs:88-106` must pass unchanged.

### SEC-14 + inline cast memory: casts go through the same queue, bounded
- Inline `cast/3` enqueues `{:cast, reply_to, input, otel_ctx}`; the result goes to `reply_to` and the updated
  agent is committed (memory persists). Exits and throws are caught in the worker, so `reply_to` always hears
  back (today only raises are).
- `:server` `cast/3` goes through `spawn_run/3`'s pending map with `{:cast, reply_to}` in place of a `from`
  (replaces `Task.start` at `:640-664`); the `:DOWN` clause sends the `:task_down` error to `reply_to`.
- New `start_link/1` option `:max_pending_runs` (pos_integer or `:infinity`, default per Q3) bounds queued +
  in-flight runs and casts. Above it, `run/3` replies `{:error, %TurnError{type: <Q3>}}` and `cast/3` sends
  `{:agent_result, id, {:error, ...}}` to `reply_to`. `run_count`/`last_run` move to completion for casts (the
  `wait_until` test `agent_process_test.exs:168-176` still passes).
- Tests: gated client, `max_pending_runs: 2`; third cast gets the refusal at once; the first two complete after
