### ParallelOrchestrator (`parallel_orchestrator.ex`)
Public: `execute/2` (:57? see below), `execute_specs/2` (`@doc false`), `execute_same_input/3`, `execute_stream/2`.
```elixir
@spec execute([agent_spec()] | [struct()], keyword() | map()) :: {:ok, execution_result()} | {:ok, list()}   # :93-94
def execute(agents, input_or_opts \\ []) do
  WorkflowSpan.span(:parallel, %{step_count: length(agents)}, fn -> do_execute(agents, input_or_opts) end)
end
@doc false
def execute_specs(agent_specs, opts), do: do_execute(agent_specs, opts)      # used by HierarchicalCoordinator :115, :165 (no 2nd span)

# :107-125
defp do_execute(agents, input) when is_list(agents) and (is_map(input) or is_binary(input)) do
  cond do
    is_binary(input) -> execute_simple_api(agents, input)
    is_map(input) and not is_map_key(input, :__struct__) -> execute_simple_api(agents, input)
    true -> execute_with_specs(agents, [])          # <<< struct input lands here: the input is DROPPED
  end
end
defp do_execute(agent_specs, opts) when is_list(agent_specs) and is_list(opts), do: execute_with_specs(agent_specs, opts)
```
How a struct input is dropped: `%BaseAgentInputSchema{}` is a map (guard passes) with `:__struct__`, so the third `cond` arm runs `execute_with_specs(agents, [])` (opts `[]`, input discarded). With spec maps (`%{id, agent, input}`) each spec runs its own `:input` and the struct is ignored; with raw agent structs (the "simple" call shape) `Map.fetch!(spec, :id)` (:~140, inside `Task.async_stream` fun) raises KeyError in a linked task, taking the caller down. Also `execute_same_input/3` (:~205) does `do_execute(agent_specs, opts)` where opts is a list so it is fine; it is the only way to give specs one struct input today.
Two return shapes: spec/opts mode -> `{:ok, %{success, results: %{id => r}, errors: %{id => e}, context, aggregated}}` (always `{:ok, _}`, even with failures, `success: false`); simple mode (`execute_simple_api` :127-149) -> `{:ok, [{:ok, r} | {:error, reason}]}` in agent order. Ids in simple mode `"agent_#{idx}"`. Never returns `{:error, _}`.
Options (spec mode only): `:shared_context, :max_concurrency(10), :timeout(300_000), :aggregate, :on_agent_complete, :ordered`.
Spec type `agent_spec` requires `:id, :agent, :input`, optional `:transform`. `prepare_input/1` (:~330): struct as-is, plain map -> `chat_message` or the map, binary -> `%{chat_message: s}`.
Moduledoc example (:8-24) and `@doc` (:~63-94) describe both call forms and need rewriting. `execute_stream/2` (`@spec ([agent_spec()], keyword()) :: Enumerable.t()`) unaffected by arity change but moduledoc "execute/2 and execute_stream/2" Telemetry text names arity /2 (:25-31). `lib/normandy/telemetry.ex:174, :281` also name `execute/execute_stream` (arity in :174 is /2).

### SequentialOrchestrator (`sequential_orchestrator.ex`)
```elixir
@spec execute([agent_spec()] | [struct()], term(), keyword()) :: {:ok, execution_result()} | {:ok, term()} | {:error, term()}   # :64-65
def execute(agents, initial_input, opts \\ []) do WorkflowSpan.span(:sequential, ..., fn -> do_execute(agents, initial_input, opts) end) end

defp do_execute(agents, input, []) when is_list(agents) and (is_map(input) or is_binary(input)) do   # :70-98
  case List.first(agents) do
    %{id: _id} -> execute_with_specs(agents, input, [])                    # specs -> {:ok, map} | {:error, map}
    _agent -> ... with {:ok, %{results: results}} <- execute_with_specs(agent_specs, input, []), do: {:ok, List.last(results)}   # simple: {:ok, last} | {:error, map}
  end
end
defp do_execute(agent_specs, initial_input, opts) when is_list(agent_specs) and is_list(opts), do: execute_with_specs(agent_specs, initial_input, opts)
```
Shapes: advanced `{:ok, %{success, results: [..], errors: [..], context}}` (with `on_error: :continue` failures stay in results as `{:error, r}`, success false) or `{:error, %{success: false, results, errors: [%{agent_id, error, input}], context}}` on `:stop`; simple mode `{:ok, last_result}` (result of `List.last([])` is `nil` for no agents) or the same `{:error, map}`. Options: `:shared_context, :on_agent_complete (id, result, ctx), :on_error (:stop|:continue), :store_intermediate`. Struct input is OK here (is_map). A `[]` opts + non-map non-binary input (e.g. a list/integer) goes to the second clause (advanced shape), so the mode switch depends on opts == [] AND first element having `:id`. Also `execute_with_messages/3` (`@spec ([agent_spec()], AgentMessage.t(), keyword()) :: {:ok, [AgentMessage.t()]}`) and a private `prepare_input` that, unlike Parallel's, uses `is_struct` guard.
Note differing `prepare_input`: Sequential `is_map(input) and not is_struct(input)`; Parallel checks `is_map_key(:__struct__)`; both same effect.
