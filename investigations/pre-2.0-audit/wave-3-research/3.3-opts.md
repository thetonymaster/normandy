## 4. Forwarding to GenServer/:gen_statem/DynamicSupervisor start (what must stay allowed)
- **None of the processes forward arbitrary start options today**; only `:name` is routed (`name:` for GenServer/DynamicSupervisor; `:gen_statem.start_link(name, mod, opts, [])` for Server). The 4th arg (start options: `:debug`, `:spawn_opt`, `:hibernate_after`, `:timeout`) is hard-coded `[]` in Server and absent in the GenServers. => Strictness does not need to *allow* `:debug/:spawn_opt/:timeout`, but note `:timeout` in `CircuitBreaker`/`AgentPool` start opts would collide semantically (CircuitBreaker's own `:timeout` = open->half-open ms, NOT a start timeout).
- `:name` is passed raw (`GenServer.name()`: atom | `{:global, t}` | `{:via, m, t}`); `Turn.Server` gets `:name` injected by `Turn.Supervisor.start_server/2` / `Horde.start_server/2` via `put_child_name/1` (registry `child_name/2`) — so the Server schema MUST allow `:name`. Likewise AgentSupervisor.start_agent passes `:restart` (and the whole list) to AgentProcess.start_link => AgentProcess schema must allow `:restart` OR `start_agent` must `Keyword.drop(:restart)` first (currently it does NOT drop). Same for AgentPool -> `start_agent(agent:, restart: :temporary)`.
- `Turn.Server.start_link` receives opts from: `Turn.Session` (`:session_id,:store,:registry,:subscriber,:handlers`, stored-server-options, `:resume_policy`, `:config` | `:template_provider`), `ResumeReaper` (thin: via Session-like opts? reaper builds via `Session`/`supervisor_mod.start_server` with `host_server_opts`), tests. Server schema keys = {store, session_id, registry, config, template_provider, resume_policy, subscriber, handlers, approval_timeout_ms, on_approval_timeout, idle_timeout_ms, name}. **Not** `:supervisor`, `:supervisor_mod`, `:template_id` (Session consumes those).
- `init/1` callbacks that read opts: Turn.Server (257), Turn.Supervisor (33), ResumeReaper (52), AgentProcess (253), AgentSupervisor (205, `DynamicSupervisor.init(opts)` — gets the rebuilt `sup_opts`, so validating in `start_link` is enough), AgentPool (264), StatefulContext (232), CircuitBreaker (240), SessionStore.ETS (72), SessionRegistry.Redis (71). Validate in `start_link` (caller process) so errors raise `ArgumentError` in the caller rather than `{:error, {exception, st}}`/exit from init; `init/1` can then read the validated list. For Turn.Server note `start_link` is invoked inside the supervisor process (`DynamicSupervisor.start_child` runs the MFA in the supervisor), so an ArgumentError from `start_link` surfaces to `Session.run`'s caller as `{:error, {%ArgumentError{}, _}}` (via supervisor `start_child` returning error), NOT a raise — acceptance test must call `Server.start_link/1` directly (raise in caller), and `Session.run/2` must validate its own keys *before* `start_server` for a raise at the entry point. Also `retry_load` re-reads `start_opts` — must keep the original opts shape.
