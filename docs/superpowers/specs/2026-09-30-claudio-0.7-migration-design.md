## Goal

One migration that moves Normandy to Claudio 0.7 and lands the revised
prompt-audit patch. Success means:

- Normandy's defaults work on Opus 4.7+ and 5.x (today the first call fails with
  a 400: `temperature` defaults to `0.9`, and thinking only exists as `budget_tokens`).
- The full suite passes.
- Every breaking change ships in **2.0.0**: a breaking conventional commit (cocogitto
  writes `CHANGELOG.md` and bumps `@version`) plus an entry in `MIGRATING-2.0.md` (D15).

## 2. W2: request option contract (approved)

All keys live in `client.options`. Each one delegates to a Claudio 0.7 helper:

| Key | Values | Claudio call |
|---|---|---|
| `thinking` | `:adaptive \| :disabled` | `enable_adaptive_thinking/2`, `disable_thinking/1` |
| `thinking_display` | `:summarized \| :omitted \| :updates` | `display:` option of `enable_adaptive_thinking/2` |
| `thinking_budget` | positive integer (models that still accept `budget_tokens`: 4.6 and earlier; Opus 4.7+, 5.x, Sonnet 5 and Fable return 400) | `enable_thinking/2` with `budget_tokens` (unchanged) |
| `effort` | `:low \| :medium \| :high \| :xhigh \| :max` | `set_effort/2` |
| `speed` | `:fast \| :standard` | `set_speed/2` |
| `inference_geo` | `:global \| :us` | `set_inference_geo/2` |
| `fallbacks` | `:default` or a list of model strings/maps | `set_fallbacks/2` |
| `task_budget` | positive integer (the total) | `set_task_budget/3`; `remaining:` only after compaction (W4) |

Rules:
- **Nothing is on by default.** An absent key leaves the request exactly as it is today.
- **Normandy raises its own `ArgumentError`** for three combinations, naming the
  conflicting keys:
  - `thinking` together with `thinking_budget`
  - `thinking_display` without `thinking: :adaptive`
  - `fallbacks` together with `stream: true`. The API does support this (the retry
    happens on the same stream), but partial output from the declining model would
    already have reached the stream callback. The message says that, not that the
    API refuses it.
- **No validation of values or model support in Normandy.** A bad value hits
  Claudio's `ArgumentError`. Unsupported pairings (a task budget on Sonnet 5, a
  total under 20,000, fallbacks outside `allowed_fallback_models`) hit the API's
  400 through the existing error path.
- **One application point:** structured-output, legacy, tool-bearing and streaming
  calls all go through `add_client_options/2` (`claudio_adapter.ex:862`).
- **`output_config` merge:** `effort`, `task_budget` and `set_output_format/2` all
  write `output_config`. Claudio 0.7 merges them. A test asserts that `format` and
  `effort` both survive in the same request.

## 3. W3 fallbacks in responses, W4 budget (approved)

### W3

- `ClaudioAdapter.content_after_last_fallback/1` returns the blocks after the last
  `fallback` block (matching `:fallback` or `"fallback"`). With no fallback block,
  it returns the list unchanged, so those responses are byte-for-byte what they are today.
- `extract_content/1` (`:1025`) and `extract_tool_uses/1` (`:912`) both use it. Text
  and tool calls (including `mcp_tool_use`) from the declining model never reach the
  output schema, the tool dispatcher or memory.
- Memory stores Normandy schemas, not raw Claudio blocks (`base_agent.ex:557,842`),
  so a `fallback` block is never replayed.
- BaseAgent never sees the raw response, so (D14) `ClaudioAdapter.converse` returns
  `{response, usage, %{served_by: Claudio.Messages.Response.served_by(raw)}}` and
  `ConverseResult.normalize/1` always yields `{response, usage, meta}`. `served_by`
  is only added when it's a string.
- `call_turn_llm` (`base_agent.ex:566`) merges `served_by` into the LLM-call stop
  metadata, which reaches the `llm call stop` telemetry **and** the
  `normandy llm call stop` log line (`base_agent.ex:1234`).
- `ConverseResult.normalize/1` raises `ArgumentError` on a 3-tuple whose third
  element isn't a map, instead of treating the tuple as an opaque response.
- Streaming is untouched, because D5 makes `fallbacks` + `stream: true` raise.
- Per the fallback doc, a non-streaming response never contains the declining
  model's partial output (the `fallback` block comes first). Tests of text *before*
  a fallback block are defensive.

### W4: budget part

What the doc says (task-budgets, "Carrying a budget across compaction", fetched
2026-09-30): *"the tokens spent before compaction are the usage of all the messages
you have removed from the history so far… Leave out anything still present in the
messages you send, including any summary you added, because the server counts those
tokens itself. Update this figure only when you replace the history this way; don't
decrement it per request."* So the figure is **gross** (what was removed), not net
(`before − after`, which under-subtracts by the summary's size).

What Normandy counts (D17):
- A task is one `BaseAgent.run`, so only messages from the **current turn** were
  ever budget spend. Earlier turns' history removed by compaction is not.
- The compactor reports a new meta key, `tokens_removed`: the estimated tokens
  (`WindowManager.estimate_message_content_tokens/1` + 10 per message, the existing
  estimator) of messages present before compaction and absent after it whose
  `turn_id` equals the memory's `current_turn_id`. A summary is new in the
  compacted memory, so it's never in the removed set.
- **Prerequisite:** both rebuild paths (`WindowManager.rebuild_memory/2` and the
  summarizer's rebuild, `summarizer.ex:217-233`) currently re-add every kept message
  under `current_turn_id`, which erases earlier turns' ids (it also breaks
  `AgentMemory.delete_turn/2` after a compaction). They must preserve each kept
  message's `turn_id`; the summary message takes `current_turn_id`. This needs
  `AgentMemory.add_message/4` with a `turn_id:` option.
- The estimate (~4 characters per token) is accepted. Exact counts would need
  `count_tokens` calls per compaction.

`Turn.State`:
- `Turn.State` gets `tokens_compacted: 0`.
  - `step/2` on `{:compaction_done, %{compacted: true, tokens_removed: n}}` adds `n`.
    Any other `meta` (`NoOp`, `Inline`'s `%{}`, `compacted: false`, a third-party
    compactor that doesn't report `tokens_removed`) leaves it unchanged. The core
    stays pure.
  - It's scoped per turn: `Turn.new/1` starts it at 0, and `Turn.Server` persists
    `Turn.State`, so the value survives a resume.
  - A `Turn.State` persisted by 1.x has no `tokens_compacted` key, so the core and
    the handler read it with `Map.get(state, :tokens_compacted, 0)` and write it
    with `Map.put/3`.
- The `call_llm` handler reads `state.tokens_compacted`:
  - At 0, it sends `task_budget` without `remaining`, and the server tracks the countdown.
  - Above 0, it sends `remaining: max(total − tokens_compacted, 0)`, and sends that
    same value on every later call in the turn.
  - It's passed to the adapter as a per-call option, `:task_budget_remaining`, next
    to `response_model`, on all four call sites (structured, legacy, tool-bearing,
    streaming) **and** on the JSON parse-retry calls (`json_deserializer.ex:318`).
  - `remaining: 0` is accepted by the API (200), so a wrong figure is silent. Tests
    must pin the number, not just its presence.
- Every interpreter passes `meta` to `Turn.step/2`, except `Inline`, which sends
  `%{}` (`inline.ex:82`) because it never compacts. Verified: `Driver`
  (`driver.ex:67`) and `Server` (`server.ex:215`) pass `meta` through.

## 4. W4: Models API catalog (approved)

**Contract change (breaking):** callbacks take the options from the `{mod, opts}`
reference. Today BaseAgent drops them (`base_agent.ex:697`).

```elixir
@callback context_window(model, opts) :: {:ok, pos_integer()} | {:error, reason}
```

`context_window` returns a result tuple instead of `pos_integer() | nil`: an unknown
model and a failed lookup are both errors. `get/2` and `supports?/3` are removed
from the behaviour (D20): nothing in `lib/` calls them, and `supports?` could only
answer `false` on a failed lookup, a silent fallback.

**`ModelCatalog.ModelsAPI`** is the default (`behaviours/config.ex:50`):
- It calls `Claudio.Models.get(claudio_client, model)` and reads `max_input_tokens`.
  A response without that field returns `{:error, {:no_context_window, model}}`.
- The client comes from `opts[:client]`. BaseAgent fills it in from the agent's
  `ClaudioAdapter` via the new `ClaudioAdapter.to_claudio_client/1` (Section 6), so
  the default needs no setup. Without a client it returns `{:error, :no_client}`.

**`ModelCatalog.Static`** (D18) stays as a module so 1.x templates, which persist
`{ModelCatalog.Static, []}` and are decoded with `binary_to_term(_, [:safe])`
(`postgres.ex:226`, `redis.ex:219`), still decode. Its
`context_window/2` delegates to `ModelsAPI.context_window/2`, and `limits/0`
and its model table are deleted. Its moduledoc marks it deprecated; it logs nothing,
and the deprecation is documented in `MIGRATING-2.0.md`. Removal is a 3.0 item.

**Memoisation without global state:**
- `BaseAgentConfig` gets `resolved_context_window: nil | {model, window}`.
- `compact_turn_memory/3` (`base_agent.ex:670`) uses it when the model matches.
  Otherwise it looks the window up and returns the updated config. `Driver`
  (`driver.ex:67`) and `Server` (`server.ex:216`) already keep the config the
  compact handler returns.
- It's keyed by model, so a model change triggers a fresh lookup. It isn't persisted
  (`Turn.Server` persists `Turn.State` and messages, not config, `server.ex:288,294`),
  so a resumed turn looks it up once more.
- The catalog is only consulted when the compactor isn't `NoOp` (the default,
  `base_agent.ex:692`) and its opts don't pin `:max_tokens` (D16).
- The memo is written with `Map.put/3`, so a `BaseAgentConfig` built under 1.x (no
  `resolved_context_window` key) doesn't raise `KeyError`.
- Coordinators that discard the config `run/2` returns (`batch/processor.ex:227`,
  the orchestrators, `agent_process.ex:609`) look the window up once per run. That's
  accepted and documented, not fixed.

**Failure (D11, D20):** a lookup error raises `Normandy.ModelCatalogError` (with
`model` and `reason`), which becomes the turn's error. Nothing is memoised on
failure, so the next turn retries. Verified: `Driver` re-raises, and `Server` runs
compaction in `spawn_task`, so it surfaces as `{:llm_error, {:task_down, {exc, stack}}}`.

**Configuration check (D20):** `BaseAgent.validate_compaction_config!/1` raises
`ArgumentError` when the compactor isn't `NoOp`, its opts don't pin `:max_tokens`,
the catalog is `ModelsAPI` or `Static`, and the client isn't a `ClaudioAdapter`.
The message names the fix (pin `:max_tokens`, or configure a catalog that works
with that client). It runs in `BaseAgent.init/1` and in `ConfigTemplate.rebuild/3`,
which builds `%BaseAgentConfig{}` directly (`config_template.ex:66`). That moves
the one failure that is knowable up front out of the turn, where it would fire
after tools have already run. Network failures still raise mid-turn.

**`WindowManager`:**
- The direct `Static` calls (`window_manager.ex:46,88`) are removed. The window
  comes from the caller: the compactor passes the agent's resolved window.
- Used on its own, `WindowManager.new/1` requires `:max_tokens` and raises
  `ArgumentError` naming the option if it's missing (breaking).

**Deleted:** `ModelCatalog.Static.limits/0`, its model table, `WindowManager.for_model/2`,
`model_limits`, and their tests. Whatever those tests covered in the compaction path
is rewritten against a stub catalog.

## 5. W6: caching that survives a tool loop (revised, D19)

The original design (D8, split the system prompt into stable and volatile blocks)
was dropped after review. It cached only the stable block, and the real cost sat
elsewhere:

- `DateTimeProvider` (`date_time_provider.ex:37-40`) writes `DateTime.utc_now()`
  to the microsecond, so the system prompt changes on every call. It's the only
  built-in provider and it's opt-in; nothing registers it by default.
- The history breakpoint (`annotate_last_user_message`, `claudio_adapter.ex:716-757`)
  only marks the last `role: "user"` message, and only when its content is list-form
  or a `ContentBlock`. Tool results are `role: "tool"`, so in a tool loop the marker
  stays on the original input; an `io_schema` input (the usual case) gets no marker
  at all. Every tool-loop iteration re-sends the whole exchange uncached. (Flagged in
  `docs/assessments/2026-07-01-framework-workflow-assessment.md:52`, finding 12.)

**Changes:**
1. **`DateTimeProvider`** returns `Date.utc_today() |> Date.to_iso8601()`
   (`"2026-09-30"`), titled "Current Date". The system prompt then changes once a day.
2. **Adapter:** when `enable_caching` is on, `ClaudioAdapter` calls
   `Claudio.Messages.Request.set_cache_control/1` (top-level automatic caching, GA,
   no beta) at all four request build sites. The API places that breakpoint on the
   last cacheable block of any role and moves it forward as the conversation grows.
   `annotate_last_user_message/1` and `auto_cache_user_message/1` are deleted.
3. **Kept:** the explicit system breakpoint (`set_system_with_cache/2`, and
   `cache_last_block/1` for list-form system content) and the last-tool breakpoint
   (`add_tools/3`). Total: 3 of the 4 allowed breakpoints. This is the caching
   guide's "robust combination for agent loops": an explicit marker on the static
   system prefix plus automatic caching for the growing tail.
4. **Not changing:** the system prompt stays one string; context stays in it; the
   `ContextProvider` protocol is unchanged. `generate_prompt/1` (W5) is the only
   generator entry point. No `generate_prompt_parts/1`, no list-form system message
   from BaseAgent, so `RetryFeedback.augment_messages/2` (which does
   `content <> feedback` on the system message) keeps working.

**Known limits (documented in `MIGRATING-2.0.md`):**
- A custom provider whose text changes per call still invalidates everything after
  the system prompt. The doc tells provider authors to keep output stable.
- The API returns 400 when a caller's own `with_cache/1` markers take all 4 slots, or
  when a caller marks the last block with a TTL different from the automatic one.
  Normandy doesn't guard against either.
- A `base_url` gateway that doesn't support top-level `cache_control` rejects it.
  The fix is `enable_caching: false`.
- Each JSON parse-retry rewrites the system prompt, so retries still miss the cache
  (out of scope, as before).
## 6. Testing (approved)

Facts that shaped this section (verified 2026-09-30):
- The existing caching tests prove nothing: `claudio_adapter_caching_test.exs:18-45`
  only checks `client.options[:enable_caching]` on a struct the test built. W6's
  breakpoint logic has no real test today.
- `add_client_options/2` is private (`claudio_adapter.ex:862`), and Normandy has
  no way to fake HTTP.
- `token_counter.ex:156` builds its Claudio client with
  `Claudio.Client.new(%{token:, version:})` and ignores `ClaudioAdapter.base_url`
  (documented as being for testing, `claudio_adapter.ex:44`).

**Test seams (small production changes):**
- `ClaudioAdapter.__apply_client_options__/3` is a public wrapper around
  `add_client_options`, following the adapter's existing `__name__` seam
  convention (`__structured_schema_for__/3`). The W2 tests call it on
  `Request.new("m")` and assert on the resulting request struct.
- `ClaudioAdapter.to_claudio_client/1` is the single conversion, and it respects
  `base_url`. `TokenCounter` and `ModelsAPI` both use it, which also fixes the
  token counter dropping `base_url`.
- `to_claudio_client/1` also merges `client.options[:req_options]` into the Req
  request (D21), the same option `OpenAICompatibleAdapter` already takes
  (`openai_compatible_adapter.ex:17,100`). Tests pass
  `req_options: [plug: {Req.Test, Name}, retry: false]` and assert on the decoded
  request body, so wire assertions run async without a port.

**HTTP fakes** (per the project's Elixir checklist): `Req.Test` stubs by default,
for the adapter wire tests and `ModelsAPI`. Bypass (`{:bypass, "~> 2.1", only: :test}`)
only where the transport itself is under test: `base_url` reaching the wire, and
`stream_converse` SSE responses if `Req.Test` can't drive Claudio's streaming `into:`.

**Tests per workstream.** Every Review Focus item is pinned on the path a user
hits, not only on a helper.
- **W1** (`test/mcp/server_config_test.exs`): exact names produce Claudio's toolset
  shape. A glob raises at call time.
- **W2** (`claudio_adapter_options_test.exs`): one test per key; one per raising
  combination, with the message naming both keys; absent and `nil` keys (all eight)
  leave the request unchanged; `format` + `effort` coexist in `output_config`.
- **W3:** the helper with zero, one and two fallback blocks (defensive, see W3).
  Wire test: a `converse` reply with a `fallback` block yields meta
  `%{served_by: "<to model>"}`. `served_by` appears in the `llm call stop`
  telemetry and the log line. `normalize/1` raises on `{resp, usage, nil}`.
- **W4 budget:**
  - `turn_test.exs`, plus a property: `tokens_compacted` only goes up, only on
    `compacted: true` with an integer `tokens_removed`, and equals the sum of the
    `tokens_removed` values (oracle independent of the implementation; generators
    include `nil`, negative and missing values).
  - Compactor: compacting earlier turns' history only leaves `tokens_removed` at 0;
    removing current-turn messages reports their estimate; a summary is not counted;
    kept messages keep their `turn_id` (both rebuild paths), and
    `AgentMemory.delete_turn/2` still works after a compaction.
  - Handler: `remaining` is left out at 0, equals `max(total − tokens_compacted, 0)`
    afterwards, and stays the same on later calls (`converse` and streaming paths).
  - Wire: `output_config.task_budget.remaining` carries the exact number through
    `converse` (structured and legacy) and `stream_converse`.
  - Resume: `tokens_compacted` survives the durable stores' encoding

## 2.0.0 migration notes (breaking changes)

These become `MIGRATING-2.0.md`.

1. `SystemPromptGenerator.generate_prompt/2` → `/1` (drop the tool-registry argument).
   The `# AVAILABLE TOOLS` section is gone: a custom `Model` that does prompt-based
   tool calling must describe tools itself from `opts[:tools]`.
2. Prompt text changed (the two "Always…" lines, an empty `# OUTPUT INSTRUCTIONS`
   heading, the context line, the OUTPUT SCHEMA and retry-feedback wording).
   Prompt snapshot tests will need updating.
3. `Normandy.MCP.ServerConfig.allow_tools/2` takes exact names (globs raise); the
   field `:tool_configuration` → `:allowed_tools`.
4. `temperature` defaults to `nil` instead of `0.9` (and `0.7` in the DSL). Set it
   explicitly if older models need it. Custom `Model` implementations now receive
   `temperature: nil` and must omit it rather than send `null`. Templates persisted
   by 1.x stored `temperature: 0.9` and restore it: re-save them, or resumed sessions
   on Opus 4.7+ get a 400.
5. `Model.converse` may return `{response, usage, meta}`, and `ClaudioAdapter` does.
   Code that calls `ClaudioAdapter` directly or wraps it and matches
   `{resp, usage}` must accept the 3-tuple. Implementations returning a bare
   response or a 2-tuple keep working.
6. `ModelCatalog`: the only callback is `context_window(model, opts)`, returning
   `{:ok, n} | {:error, reason}`; `get` and `supports?` are gone.
7. `ModelsAPI` is the default catalog. `ModelCatalog.Static` is deprecated (it
   delegates to `ModelsAPI`) and will be removed in 3.0. Compaction now makes one
   Models API call per model per config, and actually runs on current models: memory
   gets truncated, and `:summarize` makes extra paid calls. A lookup failure fails
   the turn (`Turn.Server` reports `{:llm_error, {:task_down, ...}}`). A non-`NoOp`
   compactor with a non-Claudio client must pin `:max_tokens`, or `init/1` raises.
   Coordinators that drop the returned config repeat the lookup each run.
8. `WindowManager.new/1` requires `:max_tokens`; `for_model/2` is gone.
9. The summarizer requires `:model` (no retired-model fallback).
10. `DateTimeProvider` emits the date only (`"2026-09-30"`, titled "Current Date").
    With `enable_caching`, Normandy no longer marks the last user message; the API's
    automatic breakpoint covers the conversation. Keep context-provider output
    stable across calls, or caching stops at the system prompt.
11. `Response.usage` from Claudio 0.7 adds keys and returns `nil` for absent fields;
    usage maps passed to telemetry and returned to callers change shape.
