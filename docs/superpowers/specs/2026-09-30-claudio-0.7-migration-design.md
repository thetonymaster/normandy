## Goal

One migration that moves Normandy to Claudio 0.7 and lands the revised
prompt-audit patch. Success means:

- Normandy's defaults work on Opus 4.7+ and 5.x (today the first call fails with
  a 400: `temperature` defaults to `0.9`, and thinking only exists as `budget_tokens`).
- The full suite passes.
- Every breaking change ships in **2.0.0** with a CHANGELOG migration note.

### W1 detail

- `lib/normandy/mcp/server_config.ex:72` does `%{claudio_config | tool_configuration: …}`,
  which raises a `KeyError` on 0.7.
- `allow_tools/2` is documented with globs (`"search_*"`, `:49-52`). Those never
  enabled anything, even on 0.6.
- New behaviour: `allow_tools/2` takes exact names and delegates to
  `Claudio.MCP.ServerConfig.allow_tools/2`, which raises `ArgumentError` on `*`/`?`
  at call time. The struct field is `:allowed_tools` (a list of names). The docs
  example is fixed, and the tests assert the new toolset shape.
- Other 0.7 fallout to check while running the suite: `Stream.parse_events/1` was
  rewritten (re-run the streaming tests). `Response.usage` adds keys and returns
  `nil` for absent documented fields, so tests comparing usage with `==` may break.
  `stop_reason` `"compaction"` becomes `:compaction`, which has no effect because
  Normandy only matches `:tool_use`. Poison was dropped by Claudio, which has no
  effect because Normandy declares `{:poison, "~> 6.0"}` itself.

## 2. W2: request option contract (approved)

All keys live in `client.options`. Each one delegates to a Claudio 0.7 helper:

| Key | Values | Claudio call |
|---|---|---|
| `thinking` | `:adaptive \| :disabled` | `enable_adaptive_thinking/2`, `disable_thinking/1` |
| `thinking_display` | `:summarized \| :omitted \| :updates` | `display:` option of `enable_adaptive_thinking/2` |
| `thinking_budget` | positive integer (pre-4.6 models only) | `enable_thinking/2` with `budget_tokens` (unchanged) |
| `effort` | `:low \| :medium \| :high \| :xhigh \| :max` | `set_effort/2` |
| `speed` | `:fast \| :standard` | `set_speed/2` |
| `inference_geo` | `:global \| :us` | `set_inference_geo/2` |
| `fallbacks` | `:default` or a list of model strings/maps | `set_fallbacks/2` |
| `task_budget` | positive integer (the total) | `set_task_budget/3`; `remaining:` only after compaction (W4) |

Rules:
- **Nothing is on by default.** An absent key leaves the request exactly as it is today.
- **Normandy raises its own `ArgumentError`** for three combinations, naming the
  conflicting keys:
  - `thinking` together with `thinking_budget`
  - `thinking_display` without `thinking: :adaptive`
  - `fallbacks` together with `stream: true` ("streaming with fallbacks is not supported")
- **No validation of values or model support in Normandy.** A bad value hits
  Claudio's `ArgumentError`. Unsupported pairings (a task budget on Sonnet 5, a
  total under 20,000, fallbacks outside `allowed_fallback_models`) hit the API's
  400 through the existing error path.
- **One application point:** structured-output, legacy, tool-bearing and streaming
  calls all go through `add_client_options/2` (`claudio_adapter.ex:862`).
- **`output_config` merge:** `effort`, `task_budget` and `set_output_format/2` all
  write `output_config`. Claudio 0.7 merges them. A test asserts that `format` and
  `effort` both survive in the same request.

## 3. W3 fallbacks in responses, W4 budget (approved)

### W3

- `ClaudioAdapter.content_after_last_fallback/1` returns the blocks after the last
  `fallback` block (matching `:fallback` or `"fallback"`). With no fallback block,
  it returns the list unchanged, so those responses are byte-for-byte what they are today.
- `extract_content/1` (`:1025`) and `extract_tool_uses/1` (`:912`) both use it. Text
  and tool calls (including `mcp_tool_use`) from the declining model never reach the
  output schema, the tool dispatcher or memory.
- Memory stores Normandy schemas, not raw Claudio blocks (`base_agent.ex:557,842`),
  so a `fallback` block is never replayed.
- `call_turn_llm` (`base_agent.ex:566`) adds
  `served_by: Claudio.Messages.Response.served_by(response)` to the LLM-call `meta`,
  which reaches the `llm call stop` telemetry and the logs.
- Streaming is untouched, because D5 makes `fallbacks` + `stream: true` raise.

### W4: budget part

- `Turn.State` gets `tokens_compacted: 0`.
  - `step/2` on `{:compaction_done, %{compacted: true, tokens_before: b, tokens_after: a}}`
    adds `b − a`. Any other `meta` (`NoOp`, `Inline`'s `%{}`, `compacted: false`)
    leaves it unchanged. The core stays pure.
  - It's scoped per turn: `Turn.new/1` starts it at 0, and `Turn.Server` persists
    `Turn.State`, so the value survives a resume.
- The `call_llm` handler reads `state.tokens_compacted`:
  - At 0, it sends `task_budget` without `remaining`, and the server tracks the countdown.
  - Above 0, it sends `remaining: max(total − tokens_compacted, 0)`, and sends that
    same value on every later call in the turn.
  - It's passed to the adapter as a per-call option, next to `response_model`.
- The compactor already reports `:tokens_before`/`:tokens_after` (`compactor.ex:17-19`).
  Every interpreter passes `meta` to `Turn.step/2`, except `Inline`, which sends
  `%{}` (`inline.ex:82`) because it never compacts.
- Per the three-interpreter rule, confirm in the plan that `Driver`, `Inline` and
  `Server` all still handle `{:compaction_done, meta}` once the core reads `meta`.
- **Open item (unconfirmed by Q):** this uses the **net** reduction (`before − after`).
  Before implementing, check whether the doc means net or gross. If it means
  gross, `WindowManager` must also report the tokens it removed.

## 4. W4: Models API catalog (approved)

**Contract change (breaking):** callbacks take the options from the `{mod, opts}`
reference. Today BaseAgent drops them (`base_agent.ex:697`).

```elixir
@callback get(model, opts) :: {:ok, map()} | {:error, reason}
@callback supports?(model, capability, opts) :: boolean()
@callback context_window(model, opts) :: {:ok, pos_integer()} | {:error, reason}
```

`context_window` returns a result tuple instead of `pos_integer() | nil`: an unknown
model and a failed lookup are both errors.

**`ModelCatalog.ModelsAPI`** is the only implementation and the default
(`behaviours/config.ex:50`):
- It calls `Claudio.Models.get(claudio_client, model)` and reads `max_input_tokens`.
  A response without that field returns `{:error, {:no_context_window, model}}`.
- The client comes from `opts[:client]`. BaseAgent fills it in from the agent's
  `ClaudioAdapter` via the new `ClaudioAdapter.to_claudio_client/1` (Section 6), so
  the default needs no setup.
- `supports?/3` reads `capabilities` from the same response.

**Memoisation without global state:**
- `BaseAgentConfig` gets `resolved_context_window: nil | {model, window}`.
- `compact_turn_memory/3` (`base_agent.ex:670`) uses it when the model matches.
  Otherwise it looks the window up and returns the updated config. `Driver`
  (`driver.ex:67`) and `Server` (`server.ex:216`) already keep the config the
  compact handler returns.
- It's keyed by model, so a model change triggers a fresh lookup. It isn't persisted
  (`Turn.Server` persists `Turn.State` and messages, not config, `server.ex:288,294`),
  so a resumed turn looks it up once more.
- The catalog is only consulted when the compactor isn't `NoOp` (the default,
  `base_agent.ex:692`).

**Failure:** a lookup error raises `Normandy.ModelCatalogError` (with `model` and
`reason`), which becomes the turn's error. Nothing is memoised on failure, so the
next turn retries.
- **To verify in the plan:** that an exception in the compact handler becomes a turn
  error in both `Driver` and `Server`. (`Server` runs compaction in `spawn_task`;
  this hasn't been traced.)

**`WindowManager`:**
- The direct `Static` calls (`window_manager.ex:46,88`) are removed. The window
  comes from the caller: the compactor passes the agent's resolved window.
- Used on its own, `WindowManager.new/1` requires `:max_tokens` and raises
  `ArgumentError` naming the option if it's missing (breaking).

**Deleted:** `ModelCatalog.Static`, `limits/0`, and their tests. Whatever those tests
covered in the compaction path is rewritten against a stub catalog.

## 5. W6: system prompt split for caching (approved)

Problem: `DateTimeProvider` (`date_time_provider.ex:37-40`) writes `DateTime.utc_now()`
into the system prompt, so no cached prefix survives past it even with
`enable_caching` on.

**Generator:**
- `SystemPromptGenerator.generate_prompt/1` keeps returning one string. The
  OpenAI-compatible path and external callers are unchanged.
- New `generate_prompt_parts/1` returns `%{stable: String.t(), volatile: String.t() | nil}`:
  - `stable`: identity and purpose, steps, output instructions, plus the
    output-schema text BaseAgent appends (`base_agent.ex:245`).
  - `volatile`: the `# EXTRA INFORMATION AND CONTEXT` section, or `nil` when there
    are no providers.
- `generate_prompt/1` is the two parts joined, byte-identical to today's output.

**BaseAgent**, at both system-message build sites (regular path around `:232`,
streaming path around `:993`):
- Caching on and `volatile` present: two text blocks,
  `[stable with cache_control: ephemeral, volatile]`.
- Otherwise: the single string, exactly as today.

**Adapter** (`claudio_adapter.ex:541-546`): `cache_last_block/1` only marks the last
block when no block is already marked. So the stable breakpoint is kept and the
volatile block stays out of the cached prefix.

**To verify in the plan:**
1. Whether `cache_last_block/1` checks every block or only the last one.
2. Whether `OpenAICompatibleAdapter` accepts a list-form system message. If it
   doesn't, BaseAgent splits only for the Claudio adapter.

**Not changing:** the context-provider protocol (no `volatile?` callback), and the
location of context, which stays in the system prompt.

## 2.0.0 migration notes (breaking changes)

1. `SystemPromptGenerator.generate_prompt/2` → `/1` (drop the tool-registry argument).
2. `Normandy.MCP.ServerConfig.allow_tools/2` takes exact names (globs raise); the
   field `:tool_configuration` → `:allowed_tools`.
3. `temperature` defaults to `nil` instead of `0.9`. Set it explicitly if older
   models need it.
4. `ModelCatalog` callbacks take `opts`, and `context_window` returns
   `{:ok, n} | {:error, reason}`.
5. `ModelCatalog.Static` is removed; `ModelsAPI` is the default. A catalog lookup
   failure fails the turn.
6. `WindowManager.new/1` requires `:max_tokens` when used standalone.
7. The summarizer requires `:model` (no retired-model fallback).
