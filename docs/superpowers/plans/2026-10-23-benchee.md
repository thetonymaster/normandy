# Benchee Benchmarks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A hand-run `mix bench` with four Benchee scripts that settle the parked measure-first findings, plus local
save/compare between commits.

**Architecture:** `benchee` is a `:dev`-only dependency. `bench/support.exs` defines `Bench.Support`, the one shared
module: run options, env-var handling and the banner. One `bench/<target>.exs` per target calls `Benchee.run/2`
directly. A function alias, `mix bench`, starts the app and `Code.require_file/1`s each script in one VM.

**Tech Stack:** Elixir 1.20, Benchee `~> 1.5`, `Normandy.Test.FakeClient` (ships in `lib/`).

**Spec:** `docs/superpowers/specs/2026-10-23-benchee-design.md`. Read it first: the Targets table and "Settled after
the builder check" are requirements.

## Global Constraints

- Dependency: `{:benchee, "~> 1.5", only: :dev}`. Nothing else is added. No HTML formatter.
- Scripts run in `MIX_ENV=dev` (`cli/0` `preferred_envs: [bench: :dev]`). They use only `lib/` code, never
  `test/support`.
- No CI job. No committed results. Saved runs go to `bench/results/<script>-<tag>.benchee`, and `/bench/results/` is
  gitignored. `git status --porcelain` stays empty after any bench run.
- Env vars: `BENCH_QUICK=1` (warmup 0.2 s, time 1 s, memory_time 0.2 s), `BENCH_SAVE=<tag>`, `BENCH_COMPARE=<tag>`.
  Defaults: warmup 1 s, time 5 s, memory_time 1 s.
- Scenario names are fixed string literals, identical across commits.
- Each script prints a banner (what it measures, the input sizes, the expected shape) and asserts once, before
  `Benchee.run/2`, that its input reaches the path it measures. A failed assertion raises.
- No fixes to `lib/` code. If a number looks bad, report it. Do not change the code.
- `mix precommit` exits 0 at the end of every task. CLAUDE.md: gate on the exit status, not on grepping the output.
- Commits only if Q approved commits for this execution run. `git add` named files only. No AI attribution lines in
  messages (Q's global rule).

## Review Focus

1. `BENCH_COMPARE=<tag>` with no saved file for that script → raises `ArgumentError` naming the missing path and the
   `BENCH_SAVE` command that would create it. Test in Task 2, Step 6.
2. `BENCH_SAVE` and `BENCH_COMPARE` set to the same tag → raises before anything runs (a save could overwrite the run
   being compared). Test in Task 2, Step 6.
3. A tag with `/`, `..`, a space or an empty value → raises (it becomes part of a file path). Test in Task 2, Step 6.
4. `mix bench bench/nope.exs` → fails with an error naming `bench/nope.exs`, not a stack of unrelated output. Test in
   Task 2, Step 6.
5. A full `mix bench` leaves no files outside `bench/results/` (no Mnesia dirs, no `tmp/`). Test in Task 6, Step 3.

### Task 1: Spike — does FakeClient streaming reach the incremental guards per delta?

Throwaway. Nothing is committed. Its answer decides whether Task 4 can be written as the spec says.

**Files:**
- Create (scratch, not in the repo): `$SCRATCH/guard_spike.exs`

**Interfaces:**
- Produces: a yes or no, plus the observed guard-call count for a 16 KB answer in 50-byte chunks with `chunk_size: 200`.
  Expected count: about 16_384 / 200 ≈ 82 incremental checks, plus a tail check and the final output check.

- [ ] **Step 1: Write the spike.** Define `CountingGuard` (`@behaviour Normandy.Guardrails.Guard`, `check/2` bumps
  `Process.get(:guard_calls, 0)` and returns `:ok`). Build `BaseAgent.init(%{client: FakeClient.new([{:text,
  chunks}]), model: "claude-opus-5-5", guardrails: [output: [{CountingGuard, []}], streaming_mode: :incremental,
  chunk_size: 200]})`, where `chunks` is a 16 KB string split into 50-byte pieces. Run `BaseAgent.stream(config, "go",
  fn _ -> :ok end)` and print the count. Use `test/agents/base_agent_streaming_guardrails_test.exs:255-275` as the
  config template.
- [ ] **Step 2: Run it.** `mix run $SCRATCH/guard_spike.exs` (dev env). Expected: `{:ok, _, _}`, and a count in 80–90.
- [ ] **Step 3: Decide.** If the count is about 1 (the deltas were merged before the guard saw them), or the guard runs in
  another process (count 0 in the caller), stop and report to Q with the observed numbers. Do not start Task 4. If
  the count is in range, record it in the Task 4 notes and continue.

### Task 2: Scaffolding + `Bench.Support` + `type_dump.exs`

**Files:**
- Modify: `mix.exs` (deps, `cli/0`, `aliases/0`, a new `defp run_bench/1` beside `run_redis_tests/1`)
- Modify: `mix.lock` (via `mix deps.get`)
- Modify: `.gitignore` (add `/bench/results/`)
- Modify: `.formatter.exs` (inputs gain `bench/**/*.exs`)
- Create: `bench/support.exs`
- Create: `bench/type_dump.exs`

**Interfaces:**
- Produces (in `bench/support.exs`, module `Bench.Support`):
  - `run_opts(script :: String.t(), extra :: keyword()) :: keyword()`. This returns the Benchee options: the time
    defaults (or the `BENCH_QUICK` values), plus `save: [path: "bench/results/#{script}-#{tag}.benchee", tag: tag]`
    when `BENCH_SAVE` is set, plus `load: path` when `BENCH_COMPARE` is set, merged with `extra` (extra wins).
    `script` is the bare name, for example `"type_dump"`.
  - `banner(title :: String.t(), sizes :: [String.t()], expected :: String.t()) :: :ok`. Prints three labelled lines.
  - `assert!(condition :: boolean(), message :: String.t()) :: :ok`. Raises `RuntimeError` with `message` when false.
- Produces (`mix.exs`): `mix bench [paths...]`. With no paths it runs `Path.wildcard("bench/*.exs")` minus
  `bench/support.exs`, sorted. Each script starts with `Code.require_file("support.exs", __DIR__)`.

- [ ] **Step 1: Add the dep and fetch it.** Add `{:benchee, "~> 1.5", only: :dev}` after `:ex_doc` in `deps/0`, then
  run `mix deps.get`. Expected: `mix.lock` gains `benchee`, `deep_merge` and `statistex`.
- [ ] **Step 2: Add the alias.** Add `bench: &run_bench/1` to `aliases/0` and `bench: :dev` to `preferred_envs`.
  `run_bench/1` calls `Mix.Task.run("app.start")`, then `Code.require_file/1` on each path. A path that does not exist
  raises `Mix.Error` with `"mix bench: no such file #{path}"` before any script runs. Add one comment line above it,
  in the style of `run_redis_tests/1`.
- [ ] **Step 3: Update `.gitignore` and `.formatter.exs`.** Gitignore `/bench/results/`. Formatter inputs gain `bench/**/*.exs`.
- [ ] **Step 4: Write `bench/support.exs`** with the three functions above. Tag rule: `~r/\A[A-Za-z0-9][A-Za-z0-9._-]*\z/`
  and no `..`. Any other tag raises `ArgumentError`, `"BENCH_SAVE=#{inspect(tag)}: tags may only use letters, digits, . _ -"`
  (`BENCH_COMPARE` likewise). An equal save and compare tag raises
  `"BENCH_SAVE and BENCH_COMPARE are both #{tag}; save under a new tag"`. A missing load file raises
  `"BENCH_COMPARE=#{tag}: no saved run at #{path}; run BENCH_SAVE=#{tag} mix bench bench/#{script}.exs first"`.
  `File.mkdir_p!("bench/results")` runs only when saving.
- [ ] **Step 5: Write `bench/type_dump.exs`.** Scenario names, fixed: `"dump :integer"`, `"dump :boolean"`,
  `"dump :map"`, `"dump :string"`, `"dump :binary"`, `"dump :date"`, `"dump :duration"`, `"dump {:array, :integer} 1k"`,
  `"cast :integer"`, `"cast {:array, :integer} 1k"`. Inputs: one valid value per type, built before the run. Assert
  each dump returns `{:ok, _}`. Banner expected shape: "constant per scalar; linear in the array. Compare with the
  `@compile {:inline}` at lib/normandy/type.ex:594 removed (see bench/README.md)".
- [ ] **Step 6: Verify the edge cases (Review Focus 1–4).** Each command must exit non-zero with the quoted text in
  its output:
  - `BENCH_QUICK=1 BENCH_COMPARE=nope mix bench bench/type_dump.exs` → `no saved run at bench/results/type_dump-nope.benchee`
  - `BENCH_SAVE=x BENCH_COMPARE=x mix bench bench/type_dump.exs` → `both x`
  - `BENCH_SAVE=../x mix bench bench/type_dump.exs` and `BENCH_SAVE= mix bench bench/type_dump.exs` → `tags may only use`
  - `mix bench bench/nope.exs` → `no such file bench/nope.exs`
- [ ] **Step 7: Verify the happy path and the comparison.** First run `BENCH_QUICK=1 BENCH_SAVE=base mix bench
  bench/type_dump.exs`. Expected: exit 0, ten scenarios, and the file `bench/results/type_dump-base.benchee`. Then run
  `BENCH_QUICK=1 BENCH_COMPARE=base mix bench bench/type_dump.exs`. Expected: each scenario listed twice, the second
  marked `(base)`, with a Comparison section. Finally `git status --porcelain` → only this task's tracked changes, no
  `bench/results`.
- [ ] **Step 8: Gate.** `mix format && mix precommit; echo "exit=$?"` → `exit=0`.
- [ ] **Step 9: Commit** (if approved). Files: `mix.exs mix.lock .gitignore .formatter.exs bench/support.exs
  bench/type_dump.exs`. Message: `chore: add Benchee, mix bench and the Type.dump benchmark`.

### Task 3: `json_regions.exs`

**Files:**
- Create: `bench/json_regions.exs`

**Interfaces:**
- Consumes: `Bench.Support.run_opts/2`, `banner/3`, `assert!/2` (Task 2).
- Calls: `Normandy.LLM.JsonDeserializer.parse_and_validate(content, schema, [])` (`lib/normandy/llm/json_deserializer.ex:164`).

- [ ] **Step 1: Define a script-local schema**, `Bench.JsonRegions.Out` (`use Normandy.Schema`, an `io_schema` with
  one required `:answer` `:string` field).
- [ ] **Step 2: Build the inputs** at 1, 30, 120 and 240 KB, using Benchee `inputs:`. Input names, fixed: `"1 KB"`,
  `"30 KB"`, `"120 KB"`, `"240 KB"`.
  - Balanced: prose padding around one valid `{"answer": "..."}` object, plus balanced code-like `{...}` blocks that
    fail to bind, so extraction walks several regions.
  - Adversarial: `String.duplicate("{\"a\": ", n)` padded to size.
  - Scenarios: `"balanced in prose"` and `"adversarial unclosed"`.
- [ ] **Step 3: Assert the paths.** Balanced at 1 KB → `{:ok, %Bench.JsonRegions.Out{answer: _}}`. Adversarial at
  1 KB → `{:error, _}`. Print the adversarial error reason once, so a reader can see that extraction ran and the input
  was not rejected early. If the reason is a size or input-limit rejection, raise via `assert!/2`.
- [ ] **Step 4: Banner and run.** Expected shape: "linear in size for both (region budget 8 * size + 1024). Before
  Wave 8 the adversarial case was quadratic: 30 KB 451 ms … 240 KB 30 s".
- [ ] **Step 5: Verify.** `BENCH_QUICK=1 mix bench bench/json_regions.exs; echo "exit=$?"` → `exit=0`, and the 240 KB
  adversarial average is under 1 s. If it is over 1 s, report the numbers to Q. Do not fix.
- [ ] **Step 6: Gate and commit** (if approved). `mix format && mix precommit` → 0. Message: `chore: add the JSON
  region extraction benchmark`.

### Task 4: `output_guards.exs`

Start only if Task 1 said yes.

**Files:**
- Create: `bench/output_guards.exs`

**Interfaces:**
- Consumes: `Bench.Support` (Task 2). Task 1's config shape and observed call count.
- Calls: `BaseAgent.init/1`, `BaseAgent.stream/3` (`lib/normandy/agents/base_agent.ex:241`),
  `Normandy.Test.FakeClient.new/1`, `Normandy.Guardrails.Builtins.RegexGuard` (two `:deny` patterns, for example an
  SSN-like pattern and a card-like digit run, neither matching the payload).

- [ ] **Step 1: Build the inputs** at 16, 64 and 256 KB. Input names, fixed: `"16 KB"`, `"64 KB"`, `"256 KB"`. Each is a
  list of 50-byte chunks of plain prose. A FakeClient script has one reply per request, so the run function builds a
  fresh `FakeClient.new([{:text, chunks}])` and config on every invocation. Keep the build cheap, and time a
  no-guard control so its cost is visible.
- [ ] **Step 2: Scenarios, fixed:** `"incremental (RegexGuard x2)"`, `"accumulate (RegexGuard x2)"` and `"no guards"`.
  All three use the default chat output schema and `chunk_size: 200`.
- [ ] **Step 3: Assert the path.** Run the 16 KB input once with a script-local counting guard (Task 1's module) placed
  ahead of RegexGuard. Assert the count is between `div(16_384, 200)` and `div(16_384, 200) + 5`, and the answer equals
  the joined chunks.
- [ ] **Step 4: Banner and run.** Expected shape: "incremental is quadratic in size (rescans the accumulated text at
  every check); accumulate and no guards are linear. The agents audit measured 3 ms at 64 KB and ~52 ms at 256 KB".
- [ ] **Step 5: Verify.** `BENCH_QUICK=1 mix bench bench/output_guards.exs; echo "exit=$?"` → `exit=0`, with all nine
  input×scenario rows printed.
- [ ] **Step 6: Gate and commit** (if approved). Message: `chore: add the incremental output guard benchmark`.
