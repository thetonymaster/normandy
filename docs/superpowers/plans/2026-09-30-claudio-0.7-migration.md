# Normandy 2.0.0: Claudio 0.7 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move Normandy to Claudio 0.7 and make its defaults work on Opus 4.7+/5.x, shipping the breaking changes as 2.0.0.

**Architecture:** Six workstreams from the spec (W1–W6), cut into 16 tasks that each leave the suite green.
- Request options and fallback-aware response reading live in `Normandy.LLM.ClaudioAdapter`, behind public `@doc false` seams.
- The task-budget countdown lives in the pure `Turn` core as one counter (`tokens_compacted`). It is fed by the compactor's gross count of this turn's removed messages, and compaction now keeps each message's turn id.
- Context windows come from a runtime `ModelCatalog.ModelsAPI`, memoised on the agent config. A setup that can't be sized is rejected when the agent is configured.
- Caching is an explicit system breakpoint plus Claudio's top-level automatic breakpoint.

**Tech Stack:** Elixir, Claudio 0.7.0 (path dependency `../Claudio` until it is published to Hex), ExUnit + StreamData, `Req.Test` (default HTTP fake, through `options[:req_options]`), Bypass (new, test-only, for transport-level tests).

**Spec:** `docs/superpowers/specs/2026-09-30-claudio-0.7-migration-design.md` (revised 2026-09-30, decisions D1–D21). Read it before starting any task. The plan argues from it.

## Global Constraints

- Branch `feat/claudio-0.7-migration`. Commit only on it, and never push.
- Claudio dependency stays `{:claudio, path: "../Claudio"}` for the whole plan. Switching to Hex `~> 0.7.0` is a pre-merge step that depends on publishing (Task 16).
- Run `mix format` before every `mix test` (project CLAUDE.md).
- If any test fails, it is fixed in the task that broke it, including tests outside the task's files (project CLAUDE.md). No `@tag :skip`, no deleting a failing assertion to get green.
- Add files to commits by name only. `git add .` and `git add -A` are forbidden.
- Commits carry no AI attribution: no `Co-Authored-By`, no "Generated with" line (Q's global CLAUDE.md overrides the harness default).
- Conventional commits. Every breaking change uses `type(scope)!:` plus a `BREAKING CHANGE:` footer, so `cog bump` produces 2.0.0 and lists it. A behaviour fix is `fix:`, not `refactor:`, so the changelog lists it.
- Never edit `@version` in `mix.exs` or `CHANGELOG.md`. cocogitto writes both at release (`cog.toml`).
- Nothing in W2 is on by default. An absent `client.options` key leaves the Claudio request exactly as it is today.
- Normandy validates option *combinations* only. Values and per-model support are left to Claudio's `ArgumentError` and the API's 400.
- No package-level state. Memoised values live on `BaseAgentConfig`.
- Error messages say what failed, what was received, and the fix. They never inspect a client value (it may hold an API key).
- HTTP fakes: `Req.Test` by default; Bypass only where transport is the subject (`base_url` reaching the wire, streaming). No test reaches api.anthropic.com, except the one red run named in Task 3.
- A test that passes on its first run was never seen red. The task report says so; it doesn't call it test-driven.

## Review Focus

Failure modes the spec implies, most likely first. Each one is pinned on the path a user hits, not only on a helper; the owning task is named.

1. **Resuming a session persisted by Normandy 1.x.** A `Turn.State` without `:tokens_compacted` must step and must send no `remaining` (Tasks 7, 8). A `BaseAgentConfig` without `:resolved_context_window` must memoise without `KeyError` (Task 10). A template naming `{ModelCatalog.Static, []}` must decode with `[:safe]` (Task 10).
2. **Compaction of earlier turns' history in a long session.** It must not reduce the task budget's `remaining`. Only this turn's removed messages count, gross, never a summary (Task 6). The number reaches the request body exactly, on the structured, legacy, JSON-retry and streaming paths (Task 8). The API accepts `remaining: 0`, so a wrong figure is silent.
3. **A non-Claude client, or a pinned `:max_tokens`, with a real compactor.** Pinned: no lookup (Task 10). Unpinned with a non-Claudio client and the default catalog: `init/1` and template rebuild raise with the fix in the message, instead of a failure mid-turn after tools ran (Task 11).
4. **A long tool loop with `enable_caching`.** The request carries top-level `cache_control`, and Normandy marks no message block; a `DateTimeProvider` no longer changes the prompt on every call (Task 14).
5. **An OpenAI-compatible agent on the new `temperature: nil` default.** `BaseAgent.run` → `converse` must leave `temperature` out of the wire body, not send `null` (Task 12).

## Decisions made after the spec was first approved (Q, 2026-09-30)

All are recorded in the spec's decisions log.

- **D14 `served_by` channel:** `ClaudioAdapter` returns `{schema, usage, %{served_by: model}}`. `ConverseResult.normalize/1` always returns a 3-tuple and still accepts bare and 2-tuple returns. A 3-tuple with a non-map meta raises.
- **D15 Release:** cocogitto. Breaking commits plus `MIGRATING-2.0.md` linked from the README. `CHANGELOG.md` and `@version` are not hand-edited.
- **D16 Catalog lookup scope:** a pinned compactor `:max_tokens` is the window, and the catalog is never called.
- **D17 Budget accounting:** gross estimated tokens of messages compaction removed that belong to the current turn. Both rebuild paths keep each message's `turn_id` (Task 6).
- **D18 `Static`:** kept as a deprecated stub that delegates to `ModelsAPI`, so 1.x templates decode.
- **D19 Caching:** `DateTimeProvider` emits the date. No system split; Claudio's top-level automatic `cache_control` replaces the last-user-message marker.
- **D20 Catalog failures:** raise (D11). An init-time check rejects a setup that can't be sized. `get` and `supports?` are dropped from the behaviour.
- **D21 `req_options`:** `to_claudio_client/1` merges `options[:req_options]`, as `OpenAICompatibleAdapter` does, so wire tests use `Req.Test`.

**Found while planning or reviewing, folded in without a new decision:**
- The DSL defaults `temperature` to `0.7` (`dsl/agent.ex:299`); it becomes `nil` with the rest of finding 1.
- `WindowManager.for_model/2` and `model_limits` only exist to read the static table, so they are deleted.
- JSON parse-retry calls rebuild their opts (`json_deserializer.ex:318`), so `:task_budget_remaining` is threaded through them (Task 8).
- `AgentMemory.history/1` drops `turn_id`. The rebuilds take turn ids from `messages/1`, which walks the same chain in the same order (Task 6).
- `function_exported?/3` is false for an unloaded module, so removal refutes call `Code.ensure_loaded!/1` first.
- The examples' Claudio pins (`~> 0.5.0`, `~> 0.1.1`) never resolved against Normandy's dependency. They are deleted (Task 15).

```elixir
defmodule Normandy.MCP.ServerConfig do
  @moduledoc """
  Configuration for server-side MCP servers passed to the Anthropic API.

  When using server-side MCP, Claude connects to the MCP server directly.
  This is simpler than client-side MCP but requires the server to be
  accessible from Anthropic's infrastructure.

  ## Example

      alias Normandy.MCP.ServerConfig

      server = ServerConfig.new("my_server", "https://mcp.example.com/sse")
      |> ServerConfig.set_auth_token("bearer-token")
      |> ServerConfig.allow_tools(["search_events", "fetch_data"])

      agent = BaseAgent.add_mcp_server(agent, server)

  """

  @type t :: %__MODULE__{
          name: String.t(),
          url: String.t(),
          authorization_token: String.t() | nil,
          allowed_tools: [String.t()] | nil
        }

  @derive {Inspect, except: [:authorization_token]}
  defstruct [:name, :url, :authorization_token, :allowed_tools]

  @doc """
  Creates a new MCP server configuration.
  """
  @spec new(String.t(), String.t()) :: t()
  def new(name, url) when is_binary(name) and is_binary(url) do
    %__MODULE__{name: name, url: url}
  end

  @doc """
  Sets the authorization token for the MCP server.
  """
  @spec set_auth_token(t(), String.t()) :: t()
  def set_auth_token(%__MODULE__{} = config, token) when is_binary(token) do
    %{config | authorization_token: token}
  end

  @doc """
  Allowlists tools from this MCP server by **exact name**; every other tool is
  disabled. A later call replaces the allowlist.

  Raises `ArgumentError` on a name containing `*` or `?`: the connector matches
  names literally, so a pattern would enable no tools at all.
  """
  @spec allow_tools(t(), [String.t()]) :: t()
  def allow_tools(%__MODULE__{} = config, names) when is_list(names) do
    # Validate now, where the mistake is, rather than when the request is built.
    _ = Claudio.MCP.ServerConfig.allow_tools(Claudio.MCP.ServerConfig.new(config.name, config.url), names)
    %{config | allowed_tools: names}
  end

  @doc """
  Converts to a `Claudio.MCP.ServerConfig` struct for API serialization.
  """
  @spec to_claudio(t()) :: Claudio.MCP.ServerConfig.t()
  def to_claudio(%__MODULE__{} = config) do
    claudio_config = Claudio.MCP.ServerConfig.new(config.name, config.url)

    claudio_config =
      if config.authorization_token do
        Claudio.MCP.ServerConfig.set_auth_token(claudio_config, config.authorization_token)
      else
        claudio_config
      end

    if config.allowed_tools do
      Claudio.MCP.ServerConfig.allow_tools(claudio_config, config.allowed_tools)
    else
      claudio_config
    end
  end
end
```

```elixir
defmodule Normandy.Agents.ConverseResult do
  @moduledoc """
  Flattens the `Normandy.Agents.Model.converse/7` return into a single
  `{response, usage, meta}` triple, so callers stop assuming one shape.

  Implementations may return `struct()`, `{struct(), usage}` or
  `{struct(), usage, meta}` (and, in raw mode, the same shapes with a binary).
  `meta` carries per-call facts that are not token usage, such as `:served_by`
  (the model that produced the message after a server-side fallback). Bare and
  2-tuple returns stay accepted so third-party `Model` implementations keep working.
  """

  @spec normalize(term()) :: {term(), map() | nil, map()}
  def normalize({response, usage, meta})
      when (is_struct(response) or is_binary(response)) and is_map(meta),
      do: {response, usage, meta}

  def normalize({response, _usage, meta}) when is_struct(response) or is_binary(response) do
    raise ArgumentError,
          "Normandy.Agents.ConverseResult.normalize/1: a {response, usage, meta} return " <>
            "needs a map as meta, got: #{inspect(meta)}. Return %{} when there is no meta."
  end

  def normalize({response, usage}) when is_struct(response) or is_binary(response),
    do: {response, usage, %{}}

  def normalize(response) when is_struct(response) or is_binary(response),
    do: {response, nil, %{}}

  def normalize(other), do: {other, nil, %{}}
end
```

### Task 6: Compaction keeps turn ids and reports `tokens_removed` (W4, budget part 1, D17)

**Why:** the task-budgets doc subtracts the **gross** usage of removed messages, never a summary, and only spend inside the task counts. A task is one `BaseAgent.run`, so only messages from the current turn count.   Contract for model capability/limit lookup.

```elixir
  `BaseAgent.compact_turn_memory/3` reads `context_window/2` to size the
  `:steering`-boundary compaction. The default impl, `ModelsAPI`, asks the
  Anthropic Models API at runtime, so new models need no Normandy release.

  from the agent's `Normandy.LLM.ClaudioAdapter`) when the reference sets none.

    the context window is the response's `max_input_tokens`.

    Needs `opts[:client]`, a Claudio client (`Req.Request`). It does no caching:
    BaseAgent memoises the window on the agent config.
    """
    @behaviour Normandy.Behaviours.ModelCatalog

    @impl true
    def context_window(model, opts) do
      with {:ok, client} <- fetch_client(opts),
           {:ok, body} <- Claudio.Models.get(client, model) do
        case body do
          %{"max_input_tokens" => n} when is_integer(n) and n > 0 -> {:ok, n}
          _ -> {:error, {:no_context_window, model}}
        end
      end
    end

    defp fetch_client(opts) do
      case Keyword.fetch(opts, :client) do
        {:ok, client} -> {:ok, client}
        :error -> {:error, :no_client}
      end
    end
  end

  defmodule Static do
    @moduledoc """
    Deprecated: use `Normandy.Behaviours.ModelCatalog.ModelsAPI`. Removed in 3.0.

    Kept so agent templates persisted by Normandy 1.x, which name
    `{ModelCatalog.Static, []}`, still decode (`binary_to_term(_, [:safe])` raises
    on an atom that doesn't exist) and still work: `context_window/2` delegates to
    `ModelsAPI`. The old static model table is gone.
    """
    @behaviour Normandy.Behaviours.ModelCatalog

    @impl true
    defdelegate context_window(model, opts), to: Normandy.Behaviours.ModelCatalog.ModelsAPI
  end
end
```

Create `MIGRATING-2.0.md`:

````markdown
# Migrating from Normandy 1.x to 2.0

Normandy 2.0 moves to Claudio 0.7 and makes its defaults work on Claude Opus 4.7 and later,
which reject sampling parameters and `budget_tokens` thinking. Each breaking change below
says what to do.

## 1. `temperature` is unset by default

`BaseAgentConfig`, `BaseAgent.init/1`, the `agent do ... end` DSL and the summarizer no longer
send a temperature (they defaulted to 0.9, 0.7 and 0.3). Pass one explicitly only for models
that accept it:

```elixir
BaseAgent.init(%{client: client, model: "claude-haiku-4-5", temperature: 0.7})
```

- **Custom `Model` implementations** now receive `temperature: nil`. Omit the field from the
  request; don't send JSON `null`, which many OpenAI-compatible servers reject.
- **Persisted session templates** stored the old default `temperature: 0.9` and restore it on
  resume. Re-save them with `temperature: nil`, or resumed sessions on Opus 4.7+ get a 400.

## 2. Prompt changes

`SystemPromptGenerator.generate_prompt/2` is now `/1`. Drop the second argument:

```elixir
SystemPromptGenerator.generate_prompt(spec)
```

- The `# AVAILABLE TOOLS` section is gone: adapters send tools through the API `tools`
  parameter. A custom `Model` that does prompt-based tool calling must describe the tools
  itself from `opts[:tools]`.
- The prompt text changed: the two "Always ..." lines are removed, an empty
  `# OUTPUT INSTRUCTIONS` heading is no longer emitted, the context section adds "Use this
  information where it is relevant to the request.", and the output-schema and
  retry-feedback wording changed. Update prompt snapshot tests.

## 3. MCP tool allowlists take exact names

`Normandy.MCP.ServerConfig.allow_tools/2` raises `ArgumentError` on `*` or `?`. The connector
matches names literally, so a glob never enabled anything. The struct field
`:tool_configuration` is now `:allowed_tools`.

```elixir
ServerConfig.allow_tools(server, ["search_events", "fetch_data"])
```

## 4. `Model.converse/7` may return `{response, usage, meta}`

`ClaudioAdapter` now returns a 3-tuple (`meta` carries `:served_by` after a server-side
fallback), and `Normandy.Agents.ConverseResult.normalize/1` always returns one.

- Implementations returning a bare response or `{response, usage}` keep working.
- Code that calls `ClaudioAdapter` directly, or wraps it (a decorator, logger or test double)
  and matches `{response, usage} = ...`, must accept the 3-tuple.
- A 3-tuple whose third element isn't a map raises `ArgumentError`.

## 5. Model catalog and compaction

- The `ModelCatalog` behaviour has one callback:

  ```elixir
  @callback context_window(model, opts) :: {:ok, pos_integer()} | {:error, term()}
  ```

  `get/1` and `supports?/2` are gone.
- `ModelCatalog.ModelsAPI` is the default. It reads `max_input_tokens` from the Anthropic
  Models API through the agent's `ClaudioAdapter`.
- `ModelCatalog.Static` is deprecated. It delegates to `ModelsAPI` and will be removed in 3.0.
  Its static model table is gone. Templates persisted by 1.x name it, which is why it stays.
- **Compaction now runs on current models.** Before, the static table didn't know them, so
  a real compactor silently did nothing. Now memory gets truncated, and the `:summarize`
  strategy makes extra paid LLM calls.
- **Compaction makes a network call:** one Models API request per model per agent config.
  Coordinators that discard the config `BaseAgent.run/2` returns (batch, orchestrators, agent
  processes) repeat it on every run.
- **A failed lookup fails the turn** with `Normandy.ModelCatalogError`. Under `Turn.Server` it
  arrives as `{:error, {:task_down, {%Normandy.ModelCatalogError{}, stack}}}`.
- **Non-Claude clients:** a non-`NoOp` compactor with a client that isn't a `ClaudioAdapter`
  must pin the window, or `BaseAgent.init/1` and `ConfigTemplate.rebuild/3` raise
  `ArgumentError`:

  ```elixir
  behaviours: %Normandy.Behaviours.Config{
    compactor: {Normandy.Behaviours.Compactor.WindowManager, [max_tokens: 200_000]}
  }
  ```

  Pinning `:max_tokens` also skips the lookup entirely (offline use).

## 6. `WindowManager.new/1` requires `:max_tokens`

`WindowManager.for_model/2` and the `:model_limits` field are removed. Pass the window:

```elixir
WindowManager.new(max_tokens: 200_000, strategy: :sliding_window)
```

## 7. The summarizer requires a model

`Summarizer` raises `ArgumentError` unless `opts[:model]` or the agent's top-level `:model` is
set. Its fallback named a retired model.

## 8. Caching and `DateTimeProvider`

- `DateTimeProvider` returns today's date (`"2026-09-30"`) titled "Current Date", instead of
  a microsecond timestamp that changed on every call and broke prompt caching.
- With `enable_caching: true`, Normandy no longer marks the last user message. Requests carry
  the API's top-level automatic `cache_control`, which also caches tool loops. Breakpoints:
  system prompt, last tool, automatic.
- Keep context-provider output stable across calls, or caching stops at the system prompt.
- The API returns 400 if your own `with_cache/1` markers fill all four breakpoint slots, or
  mark the last block with a TTL different from the automatic one's.
- A `base_url` gateway that doesn't support top-level `cache_control` rejects it; set
  `enable_caching: false` there.

## 9. Usage maps

Claudio 0.7's `Response.usage` adds keys and returns `nil` for absent documented fields. The
usage maps in telemetry and those returned to callers change shape.

## New, non-breaking

- `client.options` on `Normandy.LLM.ClaudioAdapter` accepts `:thinking`
  (`:adaptive | :disabled`), `:thinking_display`, `:effort`, `:speed`, `:inference_geo`,
  `:fallbacks` and `:task_budget`. Nothing is sent unless set. See the adapter's moduledoc.
- `:fallbacks` is rejected on streaming calls: partial output from a declining model would
  already have reached the stream callback.
- With `:task_budget`, Normandy sends the total and, after in-turn compaction, a fixed
  `remaining` that subtracts the tokens compaction removed from the current turn.
- `:req_options` is merged into the Req client, as on `OpenAICompatibleAdapter`.
- `served_by` appears in `[:normandy, :agent, :llm_call, :stop]` telemetry and the
  `normandy llm call stop` log line after a server-side fallback.
- Compaction keeps each message's turn id, so `AgentMemory.delete_turn/2` works after a
  compaction.
````
