# Normandy 2.0.0: Claudio 0.7 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move Normandy to Claudio 0.7 and make its defaults work on Opus 4.7+/5.x, shipping the breaking changes as 2.0.0.

**Architecture:** Six workstreams from the spec (W1–W6), cut into 14 tasks that each leave the suite green. Request options and fallback-aware response reading live in `Normandy.LLM.ClaudioAdapter` behind public `@doc false` seams. The task-budget countdown lives in the pure `Turn` core as one counter (`tokens_compacted`). Context windows come from a runtime `ModelCatalog.ModelsAPI`, memoised on the agent config. The system prompt splits into a cached stable block and an uncached volatile block.

**Tech Stack:** Elixir, Claudio 0.7.0 (path dependency `../Claudio` until it is published to Hex), ExUnit + StreamData, Bypass (new, test-only).

**Spec:** `docs/superpowers/specs/2026-09-30-claudio-0.7-migration-design.md`. Read it before starting any task. This plan argues from it; where the plan deviates, the deviation is listed under "Decisions made after the spec".

## Global Constraints

- Branch `feat/claudio-0.7-migration`. Commit only on it, and never push.
- Claudio dependency stays `{:claudio, path: "../Claudio"}` for the whole plan. Switching to Hex `~> 0.7.0` is a pre-merge step that depends on publishing (Task 14).
- Run `mix format` before every `mix test` (project CLAUDE.md).
- If any test fails, it is fixed in the task that broke it, including tests outside the task's files (project CLAUDE.md). No `@tag :skip`, no deleting a failing assertion to get green.
- Add files to commits by name only. `git add .` and `git add -A` are forbidden.
- Commits carry no AI attribution: no `Co-Authored-By`, no "Generated with" line (Q's global CLAUDE.md overrides the harness default).
- Conventional commits. Every breaking change uses `type(scope)!:` plus a `BREAKING CHANGE:` footer, so `cog bump` produces 2.0.0 and lists it.
- Never edit `@version` in `mix.exs` or `CHANGELOG.md`. cocogitto writes both at release (`cog.toml`).
- Nothing in W2 is on by default. An absent `client.options` key leaves the Claudio request exactly as it is today.
- Normandy validates option *combinations* only. Values and per-model support are left to Claudio's `ArgumentError` and the API's 400.
- No package-level state. Memoised values live on `BaseAgentConfig`.
- Error messages say what failed, what was received, and the fix.

## Review Focus

Failure modes the spec implies but never pins with a test, most likely first. Each one has a test in the task named.

1. **Resuming a turn persisted by Normandy 1.x.** Redis and Postgres store `Turn.State` with `term_to_binary`, so a pre-2.0 state decodes without `:tokens_compacted`. A resumed turn must keep working, with `remaining` treated as never compacted, and must not raise `KeyError`. Tests in Task 6 (core) and Task 7 (handler).
2. **An OpenAI-compatible agent on the new `temperature: nil` default.** `OpenAICompatibleAdapter.build_body/4` currently sends `"temperature" => nil`, which goes out as JSON `null`. It must leave the key out. Test in Task 10.
3. **A streaming agent with `task_budget` after in-turn compaction.** The streaming `call_llm` handler must send the same sticky `remaining` as the non-streaming one. Test in Task 7.
4. **A compactor that pins `:max_tokens`, or a non-Claudio client.** Neither may touch the Models API, and neither may fail the turn because a lookup it doesn't need failed. Test in Task 9.
5. **A response that is only a refusal plus a `fallback` block, with no text after it.** `extract_content/1` must return `""`, not the declining model's text. Test in Task 5.

## Decisions made after the spec (Q, 2026-09-30)

- **D14 `served_by` channel:** widen the converse return. `ClaudioAdapter` returns `{schema, usage, %{served_by: model}}`. `ConverseResult.normalize/1` always returns a 3-tuple `{response, usage, meta}`, and still accepts a bare struct or a 2-tuple from third-party `Model` implementations.
- **D15 Release:** releases go through cocogitto, using breaking commits plus `MIGRATING-2.0.md` linked from the README. `CHANGELOG.md` and `@version` are not hand-edited.
- **D16 Catalog lookup scope:** when the compactor's opts pin `:max_tokens`, that value is the window and the catalog is never called. Otherwise, a non-`NoOp` compactor resolves the window through the catalog, and a failure fails the turn (the approved D11).
- **Found while planning, folded in without a new decision:**
  - `cache_last_block/1` only inspects the last block. The system-list path gets an "any block already marked?" guard, so the stable breakpoint is the only one (spec Section 5, check 1).
  - `OpenAICompatibleAdapter` rejects list-form system content (`openai_compatible_adapter.ex:56-59`), so the split is Claudio-only. It is gated on `%ClaudioAdapter{options: %{enable_caching: true}}` (spec Section 5, check 2).
  - The DSL defaults `temperature` to `0.7` (`dsl/agent.ex:299`). It becomes `nil` with the rest of finding 1.
  - `WindowManager.for_model/2` and the `model_limits` field only exist to read `Static`, so they are deleted along with it.
  - `ModelsAPI.supports?/3` reads the API's capability names (`"image_input"`, `"thinking"`, …). The old `:vision`/`:tools`/`:streaming` atoms no longer match. This goes in the migration notes.

defmodule Normandy.MCP.ServerConfig do
  @moduledoc """
  Configuration for server-side MCP servers passed to the Anthropic API.

  When using server-side MCP, Claude connects to the MCP server directly.
  This is simpler than client-side MCP but requires the server to be
  accessible from Anthropic's infrastructure.

  ## Example

      alias Normandy.MCP.ServerConfig

      server = ServerConfig.new("my_server", "https://mcp.example.com/sse")
      |> ServerConfig.set_auth_token("bearer-token")
      |> ServerConfig.allow_tools(["search_events", "fetch_data"])

      agent = BaseAgent.add_mcp_server(agent, server)

  """

  @type t :: %__MODULE__{
          name: String.t(),
          url: String.t(),
          authorization_token: String.t() | nil,
          allowed_tools: [String.t()] | nil
        }

  @derive {Inspect, except: [:authorization_token]}
  defstruct [:name, :url, :authorization_token, :allowed_tools]

  @doc """
  Creates a new MCP server configuration.
  """
  @spec new(String.t(), String.t()) :: t()
  def new(name, url) when is_binary(name) and is_binary(url) do
    %__MODULE__{name: name, url: url}
  end

  @doc """
  Sets the authorization token for the MCP server.
  """
  @spec set_auth_token(t(), String.t()) :: t()
  def set_auth_token(%__MODULE__{} = config, token) when is_binary(token) do
    %{config | authorization_token: token}
  end

  @doc """
  Allowlists tools from this MCP server by **exact name**; every other tool is
  disabled. A later call replaces the allowlist.

  Raises `ArgumentError` on a name containing `*` or `?`: the connector matches
  names literally, so a pattern would enable no tools at all.
  """
  @spec allow_tools(t(), [String.t()]) :: t()
  def allow_tools(%__MODULE__{} = config, names) when is_list(names) do
    # Validate now, where the mistake is, rather than when the request is built.
    _ = Claudio.MCP.ServerConfig.allow_tools(Claudio.MCP.ServerConfig.new(config.name, config.url), names)
    %{config | allowed_tools: names}
  end

  @doc """
  Converts to a `Claudio.MCP.ServerConfig` struct for API serialization.
  """
  @spec to_claudio(t()) :: Claudio.MCP.ServerConfig.t()
  def to_claudio(%__MODULE__{} = config) do
    claudio_config = Claudio.MCP.ServerConfig.new(config.name, config.url)

    claudio_config =
      if config.authorization_token do
        Claudio.MCP.ServerConfig.set_auth_token(claudio_config, config.authorization_token)
      else
        claudio_config
      end

    if config.allowed_tools do
      Claudio.MCP.ServerConfig.allow_tools(claudio_config, config.allowed_tools)
    else
      claudio_config
    end
  end
end
```

defmodule Normandy.Agents.ConverseResult do
  @moduledoc """
  Flattens the `Normandy.Agents.Model.converse/7` return into a single
  `{response, usage, meta}` triple, so callers stop assuming one shape.

  Implementations may return `struct()`, `{struct(), usage}` or
  `{struct(), usage, meta}` (and, in raw mode, the same shapes with a binary).
  `meta` carries per-call facts that are not token usage, such as `:served_by`
  (the model that produced the message after a server-side fallback). Bare and
  2-tuple returns stay accepted so third-party `Model` implementations keep working.
  """

  @spec normalize(term()) :: {term(), map() | nil, map()}
  def normalize({response, usage, meta})
      when (is_struct(response) or is_binary(response)) and is_map(meta),
      do: {response, usage, meta}

  def normalize({response, usage}) when is_struct(response) or is_binary(response),
    do: {response, usage, %{}}

  def normalize(response) when is_struct(response) or is_binary(response),
    do: {response, nil, %{}}

  def normalize(other), do: {other, nil, %{}}
end
```

defmodule Normandy.Behaviours.ModelCatalog do
  @moduledoc """
  Contract for model capability/limit lookup.

  `BaseAgent.compact_turn_memory/3` reads `context_window/2` to size the
  `:steering`-boundary compaction. The default impl, `ModelsAPI`, asks the
  Anthropic Models API at runtime, so new models need no Normandy release.

  Callbacks receive the `opts` from the `{module, opts}` reference in
  `Normandy.Behaviours.Config`. BaseAgent adds `:client` (a Claudio client built
  from the agent's `Normandy.LLM.ClaudioAdapter`) when the reference sets none.
  """

  @callback get(model :: String.t(), opts :: keyword()) :: {:ok, map()} | {:error, term()}
  @callback supports?(model :: String.t(), capability :: atom(), opts :: keyword()) :: boolean()
  @callback context_window(model :: String.t(), opts :: keyword()) ::
              {:ok, pos_integer()} | {:error, term()}

  defmodule ModelsAPI do
    @moduledoc """
    Default ModelCatalog: `GET /v1/models/{model}` through `Claudio.Models.get/2`.

    `context_window/2` is the response's `max_input_tokens`. `supports?/3` reads
    `capabilities[name]["supported"]` using the API's capability names (for
    example `:image_input`, `:structured_outputs`, `:thinking`).

    Needs `opts[:client]`, a Claudio client (`Req.Request`). It does no caching:
    BaseAgent memoises the window on the agent config.
    """
    @behaviour Normandy.Behaviours.ModelCatalog

    @impl true
    def get(model, opts) do
      case Keyword.fetch(opts, :client) do
        {:ok, client} -> Claudio.Models.get(client, model)
        :error -> {:error, :no_client}
      end
    end

    @impl true
    def context_window(model, opts) do
      with {:ok, body} <- get(model, opts) do
        case body do
          %{"max_input_tokens" => n} when is_integer(n) and n > 0 -> {:ok, n}
          _ -> {:error, {:no_context_window, model}}
        end
      end
    end

    @impl true
    def supports?(model, capability, opts) when is_atom(capability) do
      case get(model, opts) do
        {:ok, %{"capabilities" => %{} = caps}} ->
          match?(%{"supported" => true}, Map.get(caps, Atom.to_string(capability)))

        _ ->
          false
      end
    end
  end
end

# Migrating from Normandy 1.x to 2.0

Normandy 2.0 moves to Claudio 0.7 and makes its defaults work on Claude Opus 4.7 and later
(which reject sampling parameters and `budget_tokens` thinking). Each breaking change below
lists what to do.

## 1. `temperature` is unset by default

`BaseAgentConfig`, `BaseAgent.init/1`, the `agent do ... end` DSL and the summarizer no longer
send a temperature (they defaulted to 0.9, 0.7 and 0.3). Pass one explicitly only for models
that accept it:

```elixir
BaseAgent.init(%{client: client, model: "claude-haiku-4-5", temperature: 0.7})
```

## 2. `SystemPromptGenerator.generate_prompt/2` is now `/1`

Tools are no longer listed in the prompt; adapters send them through the API `tools`
parameter. Drop the second argument:

```elixir
SystemPromptGenerator.generate_prompt(spec)
```

## 3. MCP tool allowlists take exact names

`Normandy.MCP.ServerConfig.allow_tools/2` raises `ArgumentError` on `*` or `?`: the connector
matches names literally, so a glob never enabled anything. The struct field
`:tool_configuration` is now `:allowed_tools`.

```elixir
ServerConfig.allow_tools(server, ["search_events", "fetch_data"])
```

## 4. Model catalog: runtime Models API, callbacks take `opts`

`ModelCatalog.Static` is removed; `ModelCatalog.ModelsAPI` (the default) reads
`max_input_tokens` from the Anthropic Models API. Custom catalogs implement:

```elixir
@callback get(model, opts) :: {:ok, map()} | {:error, term()}
@callback supports?(model, capability, opts) :: boolean()
@callback context_window(model, opts) :: {:ok, pos_integer()} | {:error, term()}
```

`supports?/3` uses the API's capability names (`:image_input`, not `:vision`).

An agent with a real compactor now fails the turn with `Normandy.ModelCatalogError` when the
window can't be looked up. To skip the lookup (offline, or a non-Claude client such as
`OpenAICompatibleAdapter`), pin the window on the compactor:

```elixir
behaviours: %Normandy.Behaviours.Config{
  compactor: {Normandy.Behaviours.Compactor.WindowManager, [max_tokens: 200_000]}
}
```

A session config template persisted by 1.x that names `ModelCatalog.Static` must be
re-saved with `ModelCatalog.ModelsAPI` (or your own catalog) before it is resumed.

## 5. `WindowManager.new/1` requires `:max_tokens`

`WindowManager.for_model/2` and the `:model_limits` field are removed. Pass the window:

```elixir
WindowManager.new(max_tokens: 200_000, strategy: :sliding_window)
```

## 6. The summarizer requires a model

`Summarizer` raises `ArgumentError` unless `opts[:model]` or the agent's `:model` is set (its
fallback named a retired model).

## 7. `Model.converse/7` may return `{response, usage, meta}`

`Normandy.Agents.ConverseResult.normalize/1` now returns a 3-tuple. Custom `Model`
implementations keep working: bare and `{response, usage}` returns are still accepted.

## New, non-breaking

`client.options` on `Normandy.LLM.ClaudioAdapter` accepts `:thinking`
(`:adaptive | :disabled`), `:thinking_display`, `:effort`, `:speed`, `:inference_geo`,
`:fallbacks` and `:task_budget`. Nothing is sent unless set. See the adapter's moduledoc.
